Experimental builds for Meta Quest 3, Quest 3S, and Quest 2, based on upstream [DroidDeck](https://github.com/Droid-Deck/DroidDeck) 0.6.7 (`b07eca3c`). These builds replace `v0.6.7-quest-experimental.1`.

## Downloads

| Headset | APK | Default resolution |
| --- | --- | --- |
| Quest 3 | `DeckDroid-quest3-experimental.apk` | 1080p |
| Quest 3S | `DeckDroid-quest3s-experimental.apk` | 1080p |
| Quest 2 | `DeckDroid-quest2-experimental.apk` | 720p |

Each APK is approximately 128 MB. Each target has a separate application ID and keeps its own settings and runtime data. Use the APK matching your headset.

## Fixed since v0.6.7-quest-experimental.1

`experimental.1` crashed before Steam's window appeared on Quest 3: `gamescope` exited with code 134 after a `vk.WaitSemaphores` failure during driver start-up. Horizon OS denies the legacy KGSL retired-timestamp query (`EACCES`/`EPERM`) that Turnip uses to wait for GPU work, so command retirement could never be observed.

- The bundled Quest adapter now records the timestamp of each submitted command per file descriptor and context and confirms retirement with nonblocking waits when the legacy query is denied. Concurrent submissions that return to userspace out of order, context recreation and ring exhaustion are handled; the adapter never fakes a retired timestamp.
- The bundled driver archives are versioned (`turnip25.1.0-quest1-r2`, `turnip26.3.0-quest2-r2`) so cached copies are replaced on update. Only a previous Quest driver selection is migrated; any other user choice is left alone.
- The local agent bridge can read the tail of a session log with secrets redacted on a release build over authorized ADB (`tools/droiddeckctl logs latest --tail`), so start-up failures can be diagnosed without enabling the Quest "Debugging tools" developer option or sharing a log ZIP.

## Changes from experimental.1 (unchanged)

- Integrates upstream Quest GPUOBJ, display, FEX, and compatibility improvements.
- Sets Quest 3 and Quest 3S to 1080p by default, with an optional 1440p preset where panel dimensions allow it. Existing user resolution settings are preserved.
- Sets Quest 2 to 720p by default. Drivers are selected from detected hardware rather than the APK target name.
- Preserves the session multicast lock for LAN discovery.
- Embeds and verifies all six add-on packs. Linux runtime and game downloads still require an internet connection.

## Verification and limitations

All three builds passed APK signature (v1/v2/v3), ZIP alignment, payload, JNI, and SHA256 checks. Targeted JVM tests: 28 passed. Quest native and tooling tests: 12 passed.

**Quest 3 was tested on hardware:** the installed APK is byte-identical to the attached Quest 3 APK, and a Steam session reached `READY` with the first frame rendered in Big Picture (2018x1080 at 72 Hz) using the bundled r2 driver. The start-up crash above did not reproduce.

**Quest 3S and Quest 2 are untested on hardware.** Sign-in, game installation, game rendering and input, sustained frame rate, thermal behaviour, and game compatibility remain unverified on every target, and no measured performance improvement is claimed. Quest 2 A6xx and DirectX 12 support remain experimental.

The APKs use the repository's **public test signing key**, not a private production signing identity. These are experimental builds even though this release is marked Latest for download visibility.
